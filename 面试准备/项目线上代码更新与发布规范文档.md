# 项目线上代码更新与发布规范文档

## 一、文档目的

规范本项目（Vue3 \+ FastAPI \+ Docker Compose）线上代码更新、版本发布、回滚、数据保障流程，确保线上更新**可追溯、可复现、可回滚、不丢数据、不污染环境**。

杜绝线上临时改代码、随意更新、版本混乱问题。

## 二、核心更新原则（面试必背）

- **线上容器禁止手动改代码、改配置**：容器重建即丢失，不合法、不可追溯

- **镜像版本固定 Tag，禁止 latest**：保证线上版本可精准定位

- **配置与代码镜像分离**：环境变量、配置全部外部 \.env 注入

- **数据库变更必须走迁移脚本**（Alembic），禁止手动改表

- **每次上线前必须备份数据**

- **更新后必须冒烟校验 \+ 日志检查**，确认业务正常

## 三、代码版本管理规范

### 1\. 分支规范

- **dev**：开发测试分支

- **main/master**：线上稳定分支，只合并测试通过代码

### 2\. 版本标签规范

每次上线打 Git Tag，对应镜像版本：

示例：v1\.0\.1、v1\.1\.0

保证：**Git版本 = 镜像版本 = 线上运行版本**

## 四、前端更新流程（Vue）

### 1\. 本地/开发机重新打包

```Plain Text
cd web
npm install
npm run build
```

打包产物：**\.\./web/dist**

### 2\. 线上更新步骤

1. 替换服务器上的 dist 目录（新打包产物）

2. 重建 Nginx 容器加载新静态资源与配置

```Plain Text
cd deploy
docker compose down web
docker compose up -d web
```

### 3\. 前端更新保障

- 静态资源挂载为只读，保证线上不被篡改

- 每次更新重建容器，确保新 dist 百分百生效

- 开启路由 fallback，刷新页面 404 问题彻底解决

## 五、后端更新流程（FastAPI）

### 1\. 代码更新

拉取最新 main 分支代码，确保本地测试通过。

### 2\. 数据库迁移（关键）

所有表结构、字段变更，必须通过 alembic 迁移脚本自动执行，不手动操作数据库。

```Plain Text
# 生成迁移脚本
alembic revision --autogenerate -m "feat: 新增xxx字段"

# 应用迁移
alembic upgrade head
```

### 3\. 构建新版本镜像

使用固定版本号，不使用 latest

```Plain Text
docker compose build backend
docker compose up -d backend
```

### 4\. 更新后校验

```Plain Text
# 查看启动日志
docker compose logs -f backend

# 检查健康接口
curl http://127.0.0.1:8000/health
```

## 六、配置更新保障（Nginx / \.env）

- **nginx\.conf** 通过挂载方式注入容器，不写进镜像

- **\.env** 统一管理数据库密码、LLM密钥、业务配置

- 配置修改后，重启对应服务即可生效，无需重新构建镜像

```Plain Text
docker compose down web
docker compose up -d web
```

## 七、数据安全保障（上线必备）

每次版本更新前，必须备份 PostgreSQL 数据：

```Plain Text
pg_dump -U 用户名 -h postgres 库名 > backup_日期_版本号.sql
```

作用：更新异常、数据错乱可一键回滚恢复。

## 八、版本回滚机制（线上兜底）

1. 发现新版本 Bug / 接口异常 / 启动失败

2. 立刻修改 compose 镜像 Tag 为上一个稳定版本

3. 重新启动容器：`docker compose up -d backend`

4. 验证业务恢复正常

**不可逆操作说明**：如果上线包含删除字段、清空数据等DDL，必须提前备份，否则无法代码回滚恢复数据。

## 九、更新完成校验清单

- ✅ 所有容器 healthy

- ✅ 后端无报错日志

- ✅ 健康检查接口 200

- ✅ 前端页面正常加载

- ✅ 登录、核心业务接口正常（无404/500）

- ✅ AI流式对话正常

## 十、面试总结话术（可直接背诵）

我项目线上更新采用**版本化、可追溯、可回滚**的发布方案。代码通过 Git 分支管理，上线打 Tag 对应镜像版本，不使用 latest 避免版本混乱。配置与镜像分离，通过 \.env 和挂载配置文件统一管理。数据库变更全部使用 Alembic 迁移脚本，上线前强制备份数据。前端更新重新打包静态资源并重建 Nginx 容器，后端更新构建新镜像并重启服务，更新后通过日志、健康接口、业务冒烟测试确认服务正常。如果出现线上问题，可快速回滚上一个稳定镜像版本，保证项目稳定迭代。
